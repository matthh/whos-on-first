## Findings

### SECURITY

#### High — S-1 (resolved this session): `sharp` HIGH CVE in production transitive dependency

**File:** `package-lock.json` (transitive via `next`'s optional dep)  
**Priority:** High  
**CVE:** GHSA-wq5f-xc86-pv6w / CVE-2026-96889  
**Description:** `sharp` < 0.35.5 bundles a vulnerable version of `librsvg` (use-after-free / CWE-416). `next` lists `sharp` as an optional peer dep (`^0.34.3 || ^0.35.4`) for image optimisation. The package was present in the lock file at 0.35.4, a version within the vulnerable range. `sharp` is used at runtime (image pipeline) rather than dev-build only, so this is a production exposure.  
**Fix applied:** `npm audit fix` upgraded `sharp` to 0.35.5 — verified no longer in `npm audit` output.

---

#### Low — L-1 (resolved this session): Google OAuth `profile.name` stored without sanitization

**File:** `src/app/api/auth/google-login-callback/route.ts:95-96`  
**Priority:** Low  
**Description:** `profile.name` from Google's token response was stored verbatim — no HTML stripping, no length cap — inconsistent with every other name-write path. React escapes output so XSS is low-risk, but it's a defence-in-depth gap first reported in AUDIT-2026-09-22.  
**Fix applied:** HTML stripping (`replace(/<[^>]*>/g, "")`) and `.slice(0, 100)` applied before insert and link, matching `roster PUT` and `admin PATCH` behaviour.

---

#### Low — L-2 (carry-forward): Dead code — `getValidAccessToken` and legacy per-coach Spotify routes

**File:** `src/lib/spotify.ts:182-215`; `src/app/api/auth/spotify-connect/route.ts`; `src/app/api/auth/spotify-callback/route.ts`  
**Priority:** Low  
**Description:** `getValidAccessToken(userId)` is exported but never imported by any route. The per-coach OAuth callback still writes `spotifyAccessToken` / `spotifyRefreshToken` to `users` but nothing reads them for outbound calls. Dead code increases maintenance surface and could mislead contributors.  
**Recommended fix:** Remove `getValidAccessToken`, and make `/api/auth/spotify-connect` and `/api/auth/spotify-callback` return 410 Gone (or remove them). Keep the `users.spotifyAccessToken` / `spotifyRefreshToken` DB columns until data migration is confirmed safe.

---

#### Low — L-3 (carry-forward): No Content-Security-Policy header

**File:** `next.config.ts`  
**Priority:** Low  
**Description:** `X-Frame-Options`, `X-Content-Type-Options`, and `Referrer-Policy` are set; no CSP. Without one, any future XSS would have no second line of defence.  
**Recommended fix:** Add to `next.config.ts` headers block:
```
Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data: https:; connect-src 'self' https://api.spotify.com https://accounts.spotify.com; frame-ancestors 'none';
```

### PERFORMANCE

#### Medium — P-1 (carry-forward): No rate limiting on expensive third-party endpoints

**Files:** `src/app/api/spotify/sync-playlist/route.ts`; `src/app/api/practice/generate-station/route.ts`  
**Priority:** Medium  
**Description:** Both routes make outbound calls to paid third-party APIs (Spotify, Anthropic) with no per-user throttling. An approved coach can call either endpoint in a tight loop, generating unbounded Spotify API quota consumption and Anthropic billing.  
**Recommended fix:** Store last-called timestamp per user (DB or Vercel KV) and return HTTP 429 if the endpoint is called more than once per 10 seconds per user. Alternatively, configure Vercel rate-limit middleware.

### MAINTAINABILITY

#### Medium — M-1 (resolved this session): `logoDataUrl` stored without size limit

**File:** `src/app/api/roster/route.ts:68-71`  
**Priority:** Medium  
**Description:** The roster `PUT` route accepted and stored `config.logoDataUrl` without any size guard. The Onboarding UI caps uploads at 2 MB client-side, but a direct API caller could POST an arbitrarily large base64 string. First reported AUDIT-2026-09-22.  
**Fix applied:** Guard added immediately after the `config` type check — returns HTTP 413 if `logoDataUrl.length > 3_000_000` (≈ 2.25 MB raw).

#### Low — L-5 (resolved this session): `spotify/search` query forwarded without length cap

**File:** `src/app/api/spotify/search/route.ts:42`  
**Priority:** Low  
**Description:** `q` was trimmed but not capped before forwarding to Spotify's search API. An authenticated user could send a very large query string, wasting server bandwidth and leaking request size to third-party logs.  
**Fix applied:** `.slice(0, 200)` added to the `q` extraction.

#### Low — L-4 (carry-forward): AI model ID may silently go stale

**File:** `src/app/api/practice/generate-station/route.ts:86`  
**Priority:** Low  
**Description:** `claude-haiku-4-5-20251001` is hardcoded with no `check:models` script or CI alert. If Anthropic retires the model, `/api/practice/generate-station` returns 502 with no CI alert. See ARCHITECTURE.md tech debt item 7.  
**Recommended fix:** Add a `check:models` npm script (pattern available in sibling project `escape-hatch-explore`) or at minimum add a comment with a review-by date.

#### Low — L-6 (carry-forward): `constraint_overrides` table is dead code at the DB layer

**File:** `src/lib/schema.ts:77-83`  
**Priority:** Low  
**Description:** Table is defined in schema and migrations, but no route or UI component reads from or writes to it. Dead DB surface with no production use.  
**Recommended fix:** Either remove the table in a migration and delete it from `schema.ts`, or add a comment explaining the intended future use.

#### Low — L-7 (carry-forward): `storage.ts` stale localStorage helpers

**File:** `src/lib/storage.ts`  
**Priority:** Low  
**Description:** `loadRoster` / `saveRoster` are no longer called from production code. `addHistoryEntry` and `clearAbsences` are still imported in `page.tsx` but as pure logic helpers that do not actually touch localStorage. The module still has `typeof window` SSR guards for code paths that aren't called.  
**Recommended fix:** Extract the two still-used functions as pure helpers into a separate file or inline them; delete the rest of `storage.ts`.

#### Low — L-8 (carry-forward): No unit test suite

**Files:** `src/lib/scheduler.ts`; `src/lib/constraints.ts`  
**Priority:** Low  
**Description:** The scheduler (backtracking solver) and constraint logic are complex pure functions with no unit tests. Behaviour is verified manually. A regression here could silently produce invalid game sheets.  
**Recommended fix:** Add Jest or Vitest with a few smoke tests for `generateGameSheet`, `validateGameSheet`, and `applyFilterSpec`.
