## Medium

### M-2 · No rate limiting on any API route — carry-over
**Files:** `src/app/api/**`

No rate-limiting middleware exists. Every API route accepts unlimited request
volume. The two most exposed routes:
- `POST /api/spotify/sync-playlist` — issues up to ~15 sequential Spotify search calls per
  request (one per player without a walk-on song) plus multiple playlist API calls.
- `POST /api/practice/generate-station` — proxies to Anthropic API per request.

Both can be triggered by any approved coach with no throttle.

**Fix:** Add per-IP or per-user rate limiting (e.g. `@upstash/ratelimit` with
Vercel KV). Sync-playlist and generate-station should have tighter limits
(e.g. 5 req/min) than read-only roster/history endpoints (e.g. 60 req/min).

---

### M-3 · Logo data-URL accepted with no server-side size cap — carry-over
**File:** `src/app/api/roster/route.ts` (PUT handler, `logoDataUrl` field, ~line 112)

Team logos stored as base64 data URIs have no server-side maximum. An oversized
upload can bloat the `teams` DB row and potentially exceed Neon's request payload
limit. The Onboarding UI caps file selection at 2 MB, but the API itself enforces
nothing, so a direct API caller bypasses this.

**Fix:** Reject `logoDataUrl` values whose `length` exceeds ~270 000 characters
(approximately 200 KB of binary content after base64 overhead). Return HTTP 413.

---

### M-4 · `constraint_overrides` table is completely unused — carry-over
**Files:** `src/lib/schema.ts`, `drizzle/0001_multi_team.sql`

The `constraint_overrides` table exists in the schema and migrations but is
never queried by any route or UI component. It is dead weight at the DB layer
and creates confusion for future contributors about whether it is intentional.

**Fix:** Drop the table in a new migration and remove the schema definition,
or wire the overrides into the solver's constraint pipeline if the feature is
actively planned.

### M-7 · AI model ID hardcoded in source — carry-over
**File:** `src/app/api/practice/generate-station/route.ts:86`

`claude-haiku-4-5-20251001` is a literal string in the route handler. When
Anthropic retires the model ID the endpoint silently returns 502 errors. There
is no equivalent of the `check:models` script used in the sibling
`escape-hatch-explore` project.

**Fix:** Extract to a named constant in a shared `lib/ai.ts` file. Add a weekly
CI step (or `npm run check:models` script) that calls the Anthropic models list
endpoint and verifies the model ID is still active.

## Low

### L-2 · No Content Security Policy header — carry-over
**File:** `next.config.ts`

The app sets `X-Frame-Options`, `X-Content-Type-Options`, and `Referrer-Policy`
but no CSP. User-supplied content (team names, player names, logo data URIs)
is rendered in the DOM. Any future `dangerouslySetInnerHTML` path would create
an XSS vector with no CSP backstop.

**Fix:** Add a CSP via `next.config.ts` headers block. At minimum:
`default-src 'self'; img-src 'self' data: https://open.spotify.com; script-src 'self' 'unsafe-inline'`
(tighten further as the app's content sources are fully inventoried).

---

### L-3 · `storage.ts` is dead code — carry-over
**File:** `src/lib/storage.ts`

`loadRoster` / `saveRoster` (localStorage) are no longer called from production
code. `page.tsx` still imports `addHistoryEntry` and `clearAbsences` from this
module, but those functions are pure logic helpers that never touch localStorage.

**Fix:** Extract `addHistoryEntry` and `clearAbsences` as pure functions into
a small `lib/history-helpers.ts` (or similar), then delete `storage.ts` entirely.
This removes dead localStorage code paths and makes the module's import surface clearer.

---

### L-4 · No test suite — carry-over
**Files:** `src/lib/scheduler.ts`, `src/lib/constraints.ts`

The backtracking scheduler and constraint logic are pure functions ideal for
unit testing but have zero coverage. An edge-case constraint change could
silently produce invalid game sheets.

**Fix:** Add `vitest` and cover the scheduler with scenario tests: minimum
bench minutes, max-per-week caps, playoff mode bench ordering, avoid-positions
post-pass, 10-player vs 13-player roster sizes.

### L-7 · `/api/admin/users` GET returns unbounded result set — carry-over
**File:** `src/app/api/admin/users/route.ts` (GET handler, line ~28)

The admin user list query has no `.limit()`. Low risk at current scale but
will degrade as user count grows.

**Fix:** Add cursor-based pagination or a hard `.limit(500)` with a documented
maximum and a note to implement pagination if it's ever hit.

### L-8 · `/api/auth/spotify-status` unnecessarily exposes `serviceUserId` — carry-over
**File:** `src/app/api/auth/spotify-status/route.ts:16–18`

The response body includes the Spotify service-account user ID (`serviceUserId`).
This value is not used by any client code for display or routing — it leaks
an internal identifier to every authenticated user.

**Fix:** Remove `serviceUserId` from the response. Return only `{ configured, linked }`.

### L-9 · Teams DELETE count-check fetches all rows — carry-over
**File:** `src/app/api/teams/[id]/route.ts:100`

```typescript
const count = await db.select({ id: teams.id }).from(teams).where(eq(teams.userId, userId));
if (count.length <= 1) { … }
```

This loads every team row to count them. Should use `COUNT(*)`.

**Fix:**
```typescript
import { sql } from "drizzle-orm";
// …
const [{ n }] = await db
  .select({ n: sql<number>`count(*)::int` })
  .from(teams)
  .where(eq(teams.userId, userId));
if (n <= 1) { … }
```

### L-10 · Middleware HMAC comparison should use `crypto.subtle.verify` — carry-over
**File:** `src/middleware.ts:43–48`

The edge middleware computes the expected HMAC with `crypto.subtle.sign` then
compares base64url strings via a manual character-by-character XOR loop. The
loop is functionally constant-time for same-length strings, but comparing
encoded strings rather than raw bytes is non-idiomatic. The cleaner, spec-correct
approach uses `crypto.subtle.verify`, which performs a constant-time comparison
on raw bytes and removes the manual loop entirely:

```typescript
const hmacBytes = Uint8Array.from(
  atob(hmac.replace(/-/g, "+").replace(/_/g, "/")),
  c => c.charCodeAt(0)
);
const valid = await crypto.subtle.verify(
  "HMAC", key, hmacBytes, new TextEncoder().encode(payload)
);
if (!valid) return null;
```

## Applied fixes this cycle

Both fixes verified with `npx tsc --noEmit` (exit 0).

### Fix 1 — H-1: Admin PATCH response leaked Spotify OAuth tokens
**File:** `src/app/api/admin/users/route.ts:159–170`

Added an explicit column projection to `.returning()` in the PATCH handler,
mirroring the safe field set already used by the GET handler. The response no
longer includes `spotifyAccessToken`, `spotifyRefreshToken`, `spotifyExpiresAt`,
`teamName`, `logoDataUrl`, or `constraintConfig`. The admin page's `User`
interface only references the projected fields, so the UI is unaffected.

### Fix 2 — L-5: `coachName` field in roster PUT had no validation
**File:** `src/app/api/roster/route.ts:121–123`

Applied the same guard used for player names: HTML tags stripped via regex,
value capped at 100 characters. This matches the validation pattern on the
same endpoint and prevents oversized or HTML-containing values from being
written to `users.name`.
