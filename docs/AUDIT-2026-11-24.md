#### Low — S-1 (carry-forward from AUDIT-2026-10-20): `spotify-status` missing approval gate

**File:** `src/app/api/auth/spotify-status/route.ts:14`  
**Description:** Checks `getUserId()` only — a `pending` or `suspended` user can discover whether the Spotify service account is configured. Low impact (boolean status disclosure only), but inconsistent with every other data-access route.  
**Recommended fix:**
```ts
const user = await getUser(request);
if (!user || (user.status !== "approved" && user.role !== "admin")) {
  return NextResponse.json({ configured: false, linked: false }, { status: 403 });
}
```

#### Low — L-2 (carry-forward since AUDIT-2026-10-06): Dead code — `getValidAccessToken` + legacy per-coach Spotify routes

**File:** `src/lib/spotify.ts:182–215`; `src/app/api/auth/spotify-connect/route.ts`; `src/app/api/auth/spotify-callback/route.ts`  
**Description:** `getValidAccessToken(userId)` is exported but imported by no route. The per-coach callback still writes `spotifyAccessToken` / `spotifyRefreshToken` to `users` but nothing reads them for outbound calls.
