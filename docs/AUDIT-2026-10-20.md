## New findings

### SECURITY

#### Low — S-new: `spotify-status` endpoint has no approval gate

**File:** `src/app/api/auth/spotify-status/route.ts:14`  
**Priority:** Low  
**Description:** `GET /api/auth/spotify-status` checks only `getUserId()` (i.e. is the session valid?) and does not verify `user.status === "approved"`. Every other data-touching route (roster, history, teams, Spotify search, sync, practice) additionally checks approval status. A `pending` or `suspended` user with a valid session token can call this endpoint and learn whether the service-account Spotify integration is configured and linked. The data returned is two booleans (`configured`, `linked`) describing app-level config — no user data is leaked — so the risk is minimal, but the inconsistency is a pattern gap.  
**Recommended fix:** Add the standard approval guard after `getUserId()`:
```ts
const user = await getUser(request);
if (!user || (user.status !== "approved" && user.role !== "admin")) {
  return NextResponse.json({ configured: false, linked: false }, { status: 403 });
}
```

## Carry-forward findings (escalations and status)

### MAINTAINABILITY

#### Medium — M-1 (escalated from L-4): AI model ID is now > 1 year old

**File:** `src/app/api/practice/generate-station/route.ts:86`  
**First flagged:** AUDIT-2026-08-11  
**Priority:** Escalated Low → **Medium** (was L-4 for 10 weeks; model is now over 1 year old)  
**Description:** `claude-haiku-4-5-20251001` was released 2025-10-01 and has never been updated. Anthropic retires models on their own schedule; the CLAUDE.md for sibling project `escape-hatch-explore` explicitly documents that `claude-sonnet-4-20250514` sat in that codebase a month past its retirement date, 404-ing in production. With the model now over 12 months old, the retirement risk has increased materially. If retired, `/api/practice/generate-station` silently returns HTTP 502 with no CI alert.  
**Recommended fix:**  
1. Check the current model ID against the Anthropic API (or Anthropic docs) and update if needed. Candidate: `claude-haiku-4-5` (alias) or the current Haiku model ID.
2. Add a `check:models` npm script (follow the pattern in `escape-hatch-explore`).

### SECURITY (carry-forward)

#### Low — L-2 (carry-forward since AUDIT-2026-10-06): Dead code — `getValidAccessToken` + legacy per-coach Spotify routes

**File:** `src/lib/spotify.ts:182–215`; `src/app/api/auth/spotify-connect/route.ts`; `src/app/api/auth/spotify-callback/route.ts`  
**Priority:** Low  
**Description:** `getValidAccessToken(userId)` is exported but imported by no route. The per-coach callback still writes `spotifyAccessToken` / `spotifyRefreshToken` to `users` but nothing reads them for outbound calls. Dead code inflates surface area and could mislead contributors.  
**Recommended fix:** Remove `getValidAccessToken`. Return 410 Gone from `/api/auth/spotify-connect` and `/api/auth/spotify-callback`, or remove them entirely. Keep the `users.spotifyAccessToken / spotifyRefreshToken` columns until a migration is confirmed safe.

**File:** `next.config.ts`

### PERFORMANCE (carry-forward)

#### Medium — P-1 (carry-forward since AUDIT-2026-09-01): No rate limiting on expensive third-party endpoints

**Files:** `src/app/api/spotify/sync-playlist/route.ts`; `src/app/api/practice/generate-station/route.ts`  
**Priority:** Medium  
**Description:** Both routes call paid external APIs (Spotify, Anthropic) with no per-user throttling. An approved coach can call either in a tight loop, generating unbounded cost.  
**Recommended fix:** Store last-called timestamp per user (DB or Vercel KV) and return HTTP 429 if called more than once per 10 seconds per user. Alternatively, configure Vercel rate-limit middleware.
